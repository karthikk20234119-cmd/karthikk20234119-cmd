### Development Workflow

```mermaid
flowchart LR
    A[Problem Definition] --> B[Research & Feasibility]
    B --> C[Architecture & Data Model]
    C --> D[Build — Backend First]
    D --> E[Build — Frontend / Integration]
    E --> F[Testing & Edge Cases]
    F --> G[Deployment]
    G --> H[Monitoring & Iteration]
    H -.feedback.-> A
```

### Core Principles

| | |
|---|---|
| **01** | A demo is not a product &mdash; auth, logging, and error handling are core requirements, not afterthoughts |
| **02** | Observability creates trust &mdash; if an agent's behavior cannot be logged, it cannot be trusted |
| **03** | Data models come first &mdash; a UI is trivial to replace; a bad schema is permanent debt |
| **04** | Ship early, iterate fast &mdash; deploy the minimum viable, highly functional unit, then scale |
| **05** | Debug from the root cause &mdash; understand the error before reaching for a quick fix |
| **06** | Maintainability is a feature &mdash; clean, documented, testable code |
